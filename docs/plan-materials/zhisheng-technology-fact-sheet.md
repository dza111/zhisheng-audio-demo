# 智声科技计划书技术事实底稿

用途：本文件是商业计划书、报名材料和答辩稿的技术事实来源。仅记录当前已经上线、已经验证或已经实现的内容；不将调试失败方案、未完成能力或无法验证的市场数据写入计划书。

更新基线：GitHub `main` 分支提交 `a072de2`。

## 1 项目当前产品形态

智声科技是面向音乐创作者、歌手及音频从业者的音乐制作服务平台。当前产品以网站为统一入口，已形成以下功能模块：

- 录音、混音、编曲、直播调试等服务页面，支持按曲风筛选并查看对应专业人员；
- 真实工程师资料页，展示简介、擅长风格、服务价格和作品试听；
- 录音、混音、编曲教学页，已接入课程视频及封面；
- 效果预设页，已展示六个 Studio One Track Preset 文件，并为试听内容预留入口；
- 设备供应页，已按麦克风、声卡、话放、监听耳机、监听音响、音频插件分类展示产品信息；
- AI 智能体，支持从站内工程师、教学、预设和设备资源中检索并给出可点击的站内推荐；
- AI 智能混音，支持用户上传伴奏与主人声音频，在网页中查看任务进度、在线播放和下载导出的混音结果。

## 2 已上线的网站与部署架构

### 2.1 前端与产品交互

- 当前网站为单页路由式 Web 应用，覆盖首页、服务分类、人员详情、教学、预设、设备、AI 智能体和 AI 智能混音页面；
- 页面中的工程师、作品试听、教学视频、预设、设备等内容均已接入真实素材或已预留真实素材入口；
- AI 浮动机器人是网站的常驻入口，支持拖拽移动和点击进入 AI 问答页面；
- AI 混音页面提供文件上传、任务步骤可视化、状态轮询、成品试听和下载。

### 2.2 云端服务

- 网站通过 Docker 容器部署到腾讯云 CloudBase；容器内运行 Python Web 服务，对外提供静态页面与 API；
- DeepSeek API Key 仅配置在服务端环境变量中，浏览器端不保存或暴露密钥；
- 线上服务地址：`https://zhisheng-ai-298879-11-1470821727.sh.run.tcloudbase.com`；
- 服务端对接口实施来源校验、基础访问频率限制和文件大小限制。

## 3 音乐垂直 AI 智能体

### 3.1 对话链路

1. 用户在网站 AI 页面提出需求，例如寻找录音教学、混音师、预设或设备；
2. 浏览器把消息发送至网站同域的 `/api/chat`，而非直接访问模型服务；
3. CloudBase 服务端读取 DeepSeek 密钥，将经过校验的对话以流式方式转发至 DeepSeek；
4. 回答以 SSE 流式形式返回网页，用户可持续看到生成结果；
5. 本地预览环境未配置模型密钥时，可安全转发至已部署的线上服务用于测试，不需要把密钥写入前端。

### 3.2 站内资源检索与推荐

- 建立了面向音乐制作场景的结构化资源知识库，包含录音师、混音师、编曲师、直播调试人员、教学视频、效果预设和设备分类；
- 用户问题会先进行站内资源匹配，返回资源名称、简介、图片和可点击的站内详情入口；
- 当问题不属于站内资源范围，例如基础音频知识解释，会补充公开网络检索结果作为回答上下文；
- 因此 AI 的定位不是通用聊天窗口，而是“音乐制作流程中的资源导航与专业问答入口”。

### 3.3 可用于计划书的真实表述

“平台将站内已审核的专业人员、服务案例、教学内容、效果预设与设备信息组织为可检索的音乐制作资源库，并通过对话式 AI 将用户需求转化为可执行的资源推荐与页面跳转。”

## 4 AI 智能混音与 Studio One 6 关键技术闭环

### 4.1 为什么采用云端加本地工作站架构

Studio One 6 是运行在 Windows 本机的专业数字音频工作站，不能在 CloudBase 云容器中直接执行。项目因此将“网站任务管理”和“专业音频工作站执行”拆分：

- CloudBase 负责接收音频、建立任务、展示进度、保存并回传结果；
- 本机 Windows Local Agent 负责安全领取任务、调用已配置的 Studio One 6 工程模板、执行导入与导出；
- 两端用带 Token 的专用接口通信，网页不直接控制本机 Studio One，也不暴露本机文件路径。

### 4.2 当前已经验证的工作流程

1. 用户在网页 AI 混音页上传 WAV 或 MP3 格式的伴奏和主人声；
2. 服务端校验文件格式、文件数量与角色。目前正式模板只接收一条伴奏和一条主人声；
3. 服务端创建混音任务，指定固定的 `ZHISHENG_DEFAULT_MIX` 专业混音模板，并将任务置入队列；
4. 运行在 Windows 本机的 Local Agent 每 5 秒轮询 CloudBase 队列，以 `MIX_AGENT_TOKEN` 完成身份校验后领取任务；
5. Local Agent 下载源文件至独立任务目录，并持续向网页回传“准备、Studio One 处理、导出、上传结果”等状态；
6. Agent 打开预先配置的 Studio One 6 `.song` 工程，使用已验证的 Studio One 宏与 Windows 原生键盘输入完成轨道选择和文件导入；
7. 轨道映射已固定：伴奏进入第 1 条 Stereo 轨道，主人声进入第 2 条 Mono 轨道，保证伴奏在上、人声在下；
8. 两条音频事件按工程起点对齐，保留工程中已有的专业处理链与混音设置；
9. Agent 调用 Studio One 的“导出混音”流程，检测到导出的 MP3 后执行格式与音频元数据检查；
10. Agent 将最终 MP3 上传回 CloudBase，网页自动变更为完成状态，并提供在线播放和下载。

### 4.3 Studio One 自动化的已验证边界

- 使用的工作站：Studio One 6，Windows 环境；
- 使用的工程：预先配置并通过结构检查的 `.song` 专业工程模板；
- 已验证操作：打开目标工程、定位第 1/2 轨、导入伴奏与主人声、调用导出混音、检测生成结果、回传 MP3；
- 自动化不隐藏、不移动、不最小化 Studio One 窗口，保留用户正常使用该软件的权利；
- Local Agent 已加入网络重连保护，并配置为 Windows 登录后后台启动，避免临时网络异常导致任务无人领取。

### 4.4 计划书中必须如实限定的表述

当前实现不是“模型直接自主完成全部 EQ、压缩、混响和母带决策”。准确的表述应为：

“平台以 AI 任务交互、流程编排与专业工程模板自动执行为基础，实现从网页提交、专业工作站处理到云端试听回传的混音协同闭环。核心音色处理由已验证的 Studio One 专业混音工程模板完成。”

后续如团队具备可量化、可复现的音频分析、参数预测、效果链推荐或风格化处理方法，应另行补充：原理、输入输出、评价指标、对照实验、适用范围和权属证明。

## 5 真实性证据清单

商业计划书或答辩可使用以下已具备或可现场核验的证据：

- 已部署的网站地址与页面截图；
- 录音、混音、编曲、直播、教学、预设、设备和 AI 页面演示；
- 工程师真实资料、作品试听、教学视频和效果预设文件；
- AI 智能体对站内资源的检索示例；
- AI 混音从上传、任务进度到最终网页试听下载的完整录屏；
- Studio One 6 工程模板截图，展示 Stereo 伴奏轨和 Mono 主人声轨的固定映射；
- 真实音频导出结果与对应任务记录。

## 6 计划书中暂不应写成既有成果的事项

- 未经真实调研支撑的用户规模、市场份额、收入、订单量、客户数量或融资金额；
- 未申请或未获得的软件著作权、专利、商标、奖项、合作协议；
- 未完成的多轨自动混音、自动母带、自动参数生成或多平台 DAW 兼容；
- 未获授权的工程师、作品、视频、预设、设备图片或品牌合作；
- 任何将 AI 说成完全替代专业混音师的表述。

## 7 待团队补充的音频技术材料

以下内容由团队掌握后补充，是计划书“核心技术壁垒”的关键：

- 已取得或准备申请的著作权、专利、商标及素材授权。
